# Contributing to Meshview

## Простые правила внесения изменений
- Коммиты: используйте понятные сообщения в стиле Conventional Commits
- Код: придерживайтесь принятого в проекте стиля и обязательно проходите линтеры и проверки перед PR
- Теги релизов: теги выпускаются на основе версии родительского репозитория

## Версионирование тегов
Формат тега:  rel-X.Y.Z.N.M, где X.Y.Z версия из родительского репозитория поверх которой делали изменения

Например
- rel-3.0.7.0.1 это fix на основе версии 3.0.7 родительского репозитория
- rel-3.0.7.1.0 это feature на основе версии 3.0.7 родительского репозитория
- rel-3.0.7.1.3 это третий фикс на основе версии 3.0.7.1 текущего репозитория

## Тестовые сборки (rc)
Перед релизом изменения проверяются тестовой сборкой из ветки PR.

- Тег: `rel-X.Y.Z.N.M-rcK`, где `X.Y.Z.N.M` это будущая версия релиза, а `K` номер сборки начиная с 1. Новый rc на каждое изменение ветки, которое нужно проверить: `-rc1`, `-rc2`, ...
- Ставится на последний коммит feature-ветки **до** merge в `master`.
- Тег аннотированный, сообщение `rcK: <что меняется> (#<issue>)`:
  ```bash
  git tag -a rel-3.0.8.1.2-rc1 -m "rc1: hop count on gateway nodes (#11)" <commit>
  git push origin rel-3.0.8.1.2-rc1
  ```
- GitHub Release для rc не создаётся.

## Релиз
После merge PR в `master`:

- Тег `rel-X.Y.Z.N.M` (без `-rc`) на merge-коммит в `master`, аннотированный, сообщение `Release X.Y.Z.N.M: <что меняется>`.
- GitHub Release на этот тег: `gh release create rel-X.Y.Z.N.M -R antekanton/meshview --title "<название>" --notes "..."`. В описании: что изменилось для пользователя, менялись ли схема БД и конфиг, строка `Закрывает #<issue>, PR: #<pr>`.

## Что происходит после push тега
Push любого тега `rel-*` (и rc, и релиза) запускает workflow `build-push-deploy` (`.github/workflows/container.yml`):

1. Собирается образ `ghcr.io/antekanton/meshview:<тег>` и `:latest`, версия и коммит передаются в сборку и видны в футере (у rc с суффиксом `-rcN`).
2. Образ сразу деплоится на сервер (`update.sh`). То есть rc тоже попадает на рабочий инстанс, на нём и проверяется.

Ход сборки: `gh run list -R antekanton/meshview -w build-push-deploy -L 1`.
